# 모드 A · 교실 전파 탐색

## 먼저 접속 환경을 확인하세요

별도 다운로드 없이 [앱 주소](https://epoko77-ai.github.io/examguard/#wireless)로 사용합니다. **Android는 Chrome 앱을 직접 실행**하고, Windows 10/11·macOS는 Chrome 또는 Edge, Chromebook은 Chrome으로 여세요. Bluetooth 어댑터·설정과 요청되는 권한이 필요합니다. 카카오톡·네이버 등 내부 브라우저에서 열었다면 주소를 복사해 Chrome 주소창에 붙여넣으세요.

**iPhone·iPad의 Safari와 일반 iOS용 Chrome은 Web Bluetooth를 지원하지 않습니다.** 홈 화면에 설치해도 모드 A를 사용할 수 없습니다. Safari에서 B·광학 검사와 C·도감을 이용할 수 있습니다. iPhone의 BLE 대안으로는 별도 Bluefy 브라우저가 있습니다. Safari·Firefox와 Linux 기본 환경은 BLE 탐색용으로 권장하지 않습니다. [자세한 기기별 접속 안내](../README.md#어떤-기기브라우저로-열어야-하나요) · [Chrome 공식 지원 환경](https://developer.chrome.com/docs/capabilities/bluetooth) · [MDN 호환성](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API#browser_compatibility)

**Bluefy 시험 경로:** [App Store에서 설치](https://apps.apple.com/kr/app/bluefy-web-ble-browser/id1492822055) → Bluefy 앱 실행 → ExamGuard 주소 붙여넣기 → Bluetooth 켜기·권한 허용 → 준비 항목 확인 → 교실 스캔 시작. [개발사의 Web Bluetooth 지원 안내](https://bluefy.app/guide.html)는 확인했지만, **ExamGuard의 이름 조건·전체 BLE 선택창 및 실제 iPhone·Bluefy·스마트안경 조합은 아직 검증하지 않았습니다.** Android/PC 대안과 구분해 실험적 경로로 안내합니다. iOS 기기 자체의 BLE 스캔 불가능을 의미하지 않습니다.

앱은 HTTPS 보안 환경과 실제 `navigator.bluetooth.requestDevice` 존재 여부로 버튼 사용 가능 여부를 정합니다. 기기 종류는 접속 안내에만 사용하며, UA 문자열만으로 탐색 성공을 보장하지 않습니다.

## 왜 첫 단계인가

ExamGuard의 목적은 수능·국가고시·학교 시험에서 스마트안경을 이용한 부정행위의 단서를 찾고 실물 확인으로 연결하는 것입니다. 모드 A가 첫 단계이며, B·C는 발견한 기기를 자세히 살피고 기종을 대조하는 단계입니다.

실시간 외부 도움을 받는 방식은 안경과 연결 기기, 연결 기기와 외부 서비스 사이의 통신 경로를 사용합니다. 흔히 고려할 수 있는 경로는 `안경 ↔ Bluetooth ↔ 스마트폰 ↔ 인터넷 ↔ 외부 AI·조력자`입니다. 이는 점검할 시나리오이며 모든 제품의 통신 구조가 같다는 뜻은 아닙니다.

휴대전화 전원을 끄고 전자기기를 수거한 뒤 남아 있는 무선 단서를 우선 확인합니다. 허용 보조기기·감독 장비·교실 밖 신호도 있으므로 발견 즉시 부정행위로 판단하지 않고 허용 여부와 실물을 확인합니다. 오프라인 저장 자료나 로컬 기능은 무선 신호 없이도 사용할 수 있어 B·C 모드를 별도로 활용할 수 있습니다.

## 감독관에게 보이는 실제 동작

1. **전원 종료·수거·허용 장비** 세 항목을 확인합니다.
2. **탐색 범위**는 **안경 관련 이름**이 기본값이며, 필요하면 **주변 BLE 전체**로 바꾼 뒤 **교실 스캔 시작**을 누릅니다. 이름 조건은 브라우저 선택창에 적용되므로 무관한 기기가 줄어듭니다. 이름이 없거나 변경된 기기는 전체 탐색으로 보완합니다.
3. 감독관이 브라우저 목록을 살펴보고 확인할 기기를 하나 선택합니다.
4. 앱은 선택한 기기의 이름, 선택 시각, 감독관이 지정한 확인 구역을 기록합니다.
5. 이름에 안경 제품명 단서가 있으면 의심 후보와 이유를 표시합니다. 다른 전자기기 이름 단서·종류 미확인도 구분하며 후보를 먼저 보여줍니다. 선택 후의 기본 목록은 허용·실물 확인 완료를 제외한 안경 후보만 표시합니다. 종류 미확인과 다른 장비는 수량을 알리고 별도 필터·전체 보기로 확인할 수 있습니다. 목록 필터는 기록한 기기에만 적용합니다. **확인할 기기**는 다른 장비 단서·허용·확인 완료 기기를 분리하고, 미확인 기기와 직접 지정한 추가 확인 항목은 유지합니다. 숨긴 기록도 전체 목록·보고서에 남습니다.
6. 허용 장비 또는 추가 확인 필요 상태는 직접 지정하고, 기관 절차에 따라 B·C 모드로 실물을 대조합니다. 이름 단서는 촬영·소유자·기종의 증거가 아닙니다.

브라우저 목록을 여는 동작과 앱이 교실 전체 신호를 자동 수집하는 동작은 다릅니다. 현재는 전자입니다. 버튼은 명시적인 감독관 조작과 브라우저 선택창을 사용하며, 백그라운드에서 은밀하게 모든 기기를 수집하지 않습니다. 상대 기기의 GATT에 연결하거나 강제로 페어링하지 않습니다. [Chrome 공식 설명](https://developer.chrome.com/docs/capabilities/bluetooth)

## 구분해야 하는 정보

| 관찰/판단 | 현재 웹앱에서 확인 가능한가 |
| --- | --- |
| 브라우저가 발견하여 선택창에 표시한 BLE 기기 | 감독관이 목록에서 확인 가능. 광고·검색 조건에 따라 누락 가능 |
| 감독관이 선택한 기기와 제공된 이름 | 기록 가능 |
| 선택창 전체 목록 | 앱에 전달되지 않음 |
| 회사 ID·광고 원자료·RSSI | 현재 requestDevice 결과에서 읽지 않음. 별도 수신기의 v2 JSON으로 가져와 복합 규칙과 대조 가능 |
| 안경이 어느 스마트폰과 페어링/연결되어 있는지 | 확인 불가 |
| 외부 인터넷·Wi-Fi·셀룰러를 사용 중인지 | 확인 불가 |
| 기종·좌석·소유자·부정행위 여부 | 이 정보만으로 확정 불가 |

모든 휴대전화·이어폰·안경이 BLE 검색 목록에 보이는 것은 아닙니다. 연결 상태, 제품의 광고 정책, BLE와 Bluetooth Classic 사용 방식에 따라 달라집니다. 빈 목록이나 선택 취소를 “기기가 없음”으로 표시하지 않는 이유입니다.

## optionalManufacturerData와 제조사 필터

| API 요소 | 역할 | 의미하지 않는 것 |
| --- | --- | --- |
| `filters[].namePrefix` | 지정한 안경 관련 이름으로 시작하는 BLE 기기만 선택창에 표시 | 검증된 기종 판별, 이름 없는/변경된 기기까지 모두 발견 |
| `acceptAllDevices: true` | 전체 탐색을 직접 선택했을 때 이름 조건 없이 BLE 선택창 요청 | 모든 전파 또는 모든 연결 기기의 완전한 목록 |
| `optionalManufacturerData` | 요청하는 제조사 데이터 접근 권한 범위 지정 | 자동 스캔 시작, 선택창 전체 반환, 스마트안경 자동 분류 |
| `filters[].manufacturerData` | 광고의 제조사 데이터를 조건으로 브라우저 선택 후보 제한 | 회사 ID만으로 제품 종류 확정 |
| 광고 관찰 API/네이티브 수신기 | 지원 환경에서 광고 내용과 수신 정보를 관찰하는 수단 | 일반 브라우저 전체에서 동일하게 사용 가능한 기능 |

현재 ExamGuard는 선택한 탐색 범위에 따라 `requestDevice({ filters: [{ namePrefix: … }, …] })` 또는 `requestDevice({ acceptAllDevices: true })`를 사용합니다. 이름 조건은 대소문자를 구분하므로 일반적인 대소문자·띄어쓰기 변형을 검색어로 넣었지만 모든 이름을 포괄하지 않습니다. 이름 조건 오류가 나도 자동으로 전체 탐색을 재요청하지 않습니다. 읽지도 않는 제조사 데이터 권한을 넣어 자동 판별 기능처럼 보이게 하지 않습니다. [Web Bluetooth 사양 원문](https://github.com/WebBluetoothCG/web-bluetooth/blob/main/index.bs) · [Chrome 제조사 데이터 필터 설명](https://developer.chrome.com/docs/capabilities/bluetooth#manufacturer-data-filter)

## 공유기·옆집 신호처럼 보이는 항목

이 웹앱은 Wi-Fi SSID 목록을 읽지 않습니다. 공유기·TV·프린터 이름이 보여도 BLE 기기가 제공한 이름의 단서입니다. 이름 조건 탐색으로 선택창의 범위를 줄이고, 선택 후에는 이름 단서·감독관 확인 상태로 목록을 나눕니다. 분류가 충돌하거나 이름을 모르면 미확인으로 남기며, 다른 장비 단서도 실물 확인 없이 허용으로 바꾸지 않습니다.

브라우저 선택 기록에는 거리·RSSI가 없습니다. 외부 수신기 RSSI도 벽·몸·안테나 영향을 받으므로 단일 임계값으로 ‘옆집’이라고 단정해 제외하지 않습니다. 같은 기기를 여러 구역에서 반복 측정하고 실물을 확인하는 기존 절차를 유지합니다.

## 제조사 코드와 시그니처의 검증 상태

- `0x01AB`: Bluetooth SIG의 Company Identifiers에서 **Meta Platforms, Inc.**로 확인했습니다.
- `0x058E`: 같은 목록에서 **Meta Platforms Technologies, LLC**로 확인했습니다.
- `0x0D53 = Luxottica`: 일부 관련 오픈소스가 이 매핑을 소개하지만, 이번에 확인한 SIG 공식 목록에서 교차 확인하지 못해 ExamGuard의 검증된 규칙으로 채택하지 않았습니다.
- Even Realities·XREAL 등: 브랜드 이름만 보고 회사 ID를 추정하지 않습니다. 실제 광고 원자료·기종·전원/연결 조건을 함께 확보한 뒤 등록해야 합니다.

회사 식별자의 소속을 확인하는 일과 그 회사의 **특정 스마트안경이 해당 코드를 어떤 상태에서 광고하는지** 검증하는 일은 별개입니다. 같은 회사의 다른 제품, 이름 변경, 공유 칩셋, 광고 부재 등에 대한 확인이 필요합니다. [Bluetooth SIG Assigned Numbers](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Assigned_Numbers/out/en/index-en.html)

## 구현한 복합 필터와 다음 개발

외부 v2 관측에 회사 ID·필수 UUID·마스크 바이트 패턴을 AND로 대조하는 엔진을 구현했습니다. 같은 회사라도 다른 조건이 부족하면 후보로 올리지 않고, 일치 규칙의 출처와 근거를 함께 보여줍니다. 서로 다른 패킷의 단서를 합치지 않습니다. 현재 예제는 가상 자료이며 실기기 규칙은 직접 검증해 제공해야 합니다. [입력·규칙 형식](SIGNATURES.md)

다음 작업은 실기기 자료와 수신기 연결입니다.

1. 알려진 실물 기기를 대상으로 전원 켬/끔, 페어링 전/후, 연결/해제 상태의 광고 자료를 수집합니다.
2. 회사 ID·서비스 UUID·이름·광고 패턴의 근거와 한계를 기록합니다. 일반 안경 주변의 다른 전자기기도 비교합니다.
3. Android/ESP32 수신기 출력의 재현 가능한 변환 어댑터를 만듭니다. 현재는 [지정 JSON](RADIO_FORMAT.md) 입력까지만 연결되어 있습니다.
4. 구현한 복합 규칙 엔진에 검증한 규칙을 연결합니다. 일치 후보·조건 부족·미분류를 구분하고 허용 여부는 감독관이 실물로 확인합니다.
5. 실제 교실에서 오탐·미탐·반복 측정 특성을 확인한 뒤 탐지 성능을 공개합니다.

Wi-Fi·셀룰러나 실제 인터넷 사용 감지는 별도의 관측 수단과 검증이 필요한 과제이며, 현재 BLE 기능의 성능으로 포함하지 않습니다.
