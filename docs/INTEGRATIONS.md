# 기존 오픈소스와 ExamGuard를 연결하는 구조

## 역할

기존 스마트안경 탐지 프로젝트는 주변 무선 신호에서 단서를 찾는 중요한 기반입니다. ExamGuard는 수능·시험장에서 그 단서를 **준비 확인 → 추가 확인 대상 선정 → 교탁 위 광학 판독 → 실물 도감 → 기록·인계**로 이어 붙이는 도구를 지향합니다.

현재 구현된 연결과 계획한 연결을 구분합니다.

| 계층 | 현재 구현 | 다음 작업 |
| --- | --- | --- |
| 브라우저 수신 | Web Bluetooth 선택창에서 선택한 기기 이름·시각 기록 | 지원 환경별 광고 관찰 가능성 검증 |
| 외부 수신기 입력 | v1(RSSI)·v2(RSSI + 광고) JSON 파일 검사·가져오기 | Nearby Glasses/ESP32 등 실제 로그 형식별 변환 어댑터 |
| 구역 비교 | 기기 키별 구역·RSSI 중앙값, 3회 이상 반복한 구역끼리 비교 | 장비·수집 조건을 포함한 검증과 실시간 연결 검토 |
| 시그니처 분류 | v2 입력의 회사 ID·UUID·마스크 바이트 복합 대조와 출처·근거 표시 | 실기기 규칙과 현장 오탐·미탐 검증 |
| 실물 확인 | B 모드 카메라·필터, C 모드 도감·사진 후보 검색 | 기종·상세 부품 사진 확대와 독립 평가 |
| 보고서 | 현장 선택·관찰·외부 측정 자료를 JSON으로 내보내기 | 기관별 인계 양식 검토 |

외부 수신기 파일을 바로 넣는 기능은 특정 제품/프로젝트와 자동으로 연결된다는 뜻이 아닙니다. 현재는 제출자가 원본을 지정 JSON으로 변환해야 하며, 앱은 해당 수신기를 제어하지 않습니다.

## 현재 데이터 계약

[`RADIO_FORMAT.md`](RADIO_FORMAT.md)에 스키마와 예제를 제공합니다. 외부 측정값에서 필요한 것은 다음과 같습니다.

| 입력 필드 | 의미 |
| --- | --- |
| `source` | 어떤 수신기·수집 방식에서 왔는지 설명 |
| `deviceKey` | 같은 점검 세션에서 같은 기기를 묶는 키 |
| `name` | 관측된 기기 이름 또는 이름 없음 표시 |
| `zone` | 수신기가 측정한 구역 |
| `rssi` | dBm 측정값 |
| `timestamp` | 시간대가 포함된 측정 시각 |
| `isDemo` | 연습 자료 여부. true이면 보고서 제외 |

v1은 제조사 광고 바이트·UUID를 읽지 않습니다. v2는 각 관측에 제조사 데이터와 서비스 UUID를 담아 복합 규칙과 대조합니다. [SIGNATURES.md](SIGNATURES.md)에 원자료·오프셋·규칙·출처 계약을 정의했습니다. 서로 다른 광고를 합치거나 데이터가 없는 필드를 추측으로 채워서는 안 됩니다. 두 형식 모두 별도 MAC 필드를 가져오지 않지만, v2 페이로드에는 식별 가능한 바이트가 포함될 수 있습니다. 규칙 엔진은 구현했으며 검증한 실기기 기본 규칙은 아직 없습니다.

## 참고한 프로젝트와 공로

- [Nearby Glasses](https://github.com/yjeanrenaud/yj_nearbyglasses): 회사 ID·이름·일부 UUID를 단서로 알리는 네이티브 탐지 접근과 오탐 가능성을 참고했습니다. 코드 라이선스는 [AGPL-3.0](https://github.com/yjeanrenaud/yj_nearbyglasses/blob/main/LICENSE)입니다.
- [MetaDetect](https://github.com/Metrix187/metadetect): 웹과 ESP32의 역할 분리, 회사 ID·서비스 UUID·이름 패턴을 함께 보는 구성을 검토했습니다. 웹 실행에는 브라우저 실험 기능을 안내하고 있으므로 이를 일반 브라우저 기본 지원과 혼동하지 않습니다. 재사용 시 [원본 라이선스](https://github.com/Metrix187/metadetect/blob/main/LICENSE)를 확인해야 합니다.
- [BLE-Scanner](https://github.com/BenGeorgie55/BLE-Scanner): ESP32 수신·로깅 장비가 별도 관측 계층을 맡는 구조를 참고했습니다. 이 프로젝트를 ExamGuard 웹 코드에 내장하지 않았으며, 각 빌드의 출력 형식·유지 상태·[원본 저장소](https://github.com/BenGeorgie55/BLE-Scanner)를 확인해야 합니다.

ExamGuard는 이들 프로젝트의 포크나 공식 통합판이 아닙니다. 현재 탐지 코드를 복사하여 MIT로 재배포하지 않습니다. 앞으로 직접 코드를 가져오는 변경은 원래 라이선스·저작자 표시와 프로젝트 라이선스의 양립성을 먼저 확인하고, 데이터 형식 변환만 하는 경우와 구분합니다.

현재 코드에 실제로 연결한 오픈소스 실행 계층은 **Transformers.js + ONNX Runtime Web + CLIP**입니다. 사진의 유사한 도감 후보를 기기 안에서 찾는 C 모드 보조 기능에 사용합니다. BLE 탐지 엔진으로 사용하는 것은 아닙니다. [제3자 고지](THIRD_PARTY.md)

## 검증이 수반되어야 하는 통합

어댑터를 추가할 때는 원본 로그의 공개 가능한 예제, 변환 전후 결과, 누락 필드 처리, 기기 키의 세션 범위, 전원·페어링·연결 상태를 함께 제출해야 합니다. 동일 회사의 다른 제품과 미등록 기기도 비교하여 후보 분류와 실제 기종 확인을 구분합니다. 수신기 성능을 비교하지 않은 상태에서 ExamGuard가 기존 탐지기보다 정확하다고 주장하지 않습니다.
