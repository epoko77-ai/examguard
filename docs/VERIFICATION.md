# 검증 범위

기준일: 2026-11-09. 최신 커밋의 통과 여부는 [GitHub Actions](https://github.com/epoko77-ai/examguard/actions)에서 확인할 수 있습니다. 공개 데모는 워크플로 검사가 통과한 빌드만 배포합니다. 배포한 커밋과 브라우저 테스트 수는 [verification.json](https://epoko77-ai.github.io/examguard/previews/verification.json)에 기록합니다.

## 자동 검증

- TypeScript의 엄격한 앱 코드 검사 및 Vite 정적 빌드. `skipLibCheck`는 Transformers.js 패키지 내부의 상속 타입 선언 충돌 때문에 사용하며 앱의 타입 검사를 끄지 않습니다.
- Node 단위 테스트 26개: RSSI 입력 경계·스키마, 반복 측정 비교, 연습/현장 보고서 분리, HTML 이스케이프, 영상 필터, 유사도 순위, 참조 벡터·출처·도감 정합성, 복합 규칙의 AND·마스크·패킷 분리·다중 후보·경계값·시각 정렬, iPhone/iPad·Android·PC 접속 안내와 API/HTTPS 판별.
- Chromium·모바일 WebKit에서 각각 9개 시나리오: 기기별 접속 안내·주소 복사 실패 대안·B/C 바로가기, 첫 화면·레이아웃·도감·오프라인, BLE 모의 선택·늦은 응답·초기화, 카메라 권한 거부·사진 대안, 기기 이름 후보·필터·이름 변경·보고서, 외부 신호 파일, 복합 규칙 입력·결과·초기화·보고서, 실제 WASM 사진 대조·캐시 후 오프라인 재실행.
- Chromium 1개 추가 시나리오: 테스트용 미디어 스트림을 연결하고 화면 정지·화면 이동·늦은 권한 응답 뒤 트랙 종료 확인. WebKit에서는 이 Canvas 스트림 픽스처 시나리오를 건너뜁니다.
- 이름 조건이 브라우저 요청에 실제 포함되는지, 공유기·TV·프린터 이름을 합성 선택창에서 제외하는지, 이름 조건 오류 후 전체 탐색을 자동 요청하지 않는지, 직접 전체 탐색을 선택해 이름 없는 기기를 확인할 수 있는지 검사합니다. 목록 분리·복원, 직접 지정한 추가 확인, 숨긴 항목의 보고서 보존도 확인합니다. 실제 주변 전파나 거리 판별 시험은 아닙니다.
- 사진 검색 중 다른 출처로 요청하지 않는지 확인합니다. 초기 앱 방문만으로 모델/대용량 WASM을 다운로드하지 않는지도 검사합니다.

총 브라우저 시나리오는 19개 통과 + 1개 환경별 건너뜀을 목표로 구성되어 있습니다. 코드 변경마다 실제 결과를 Actions에서 확인하세요. 스크린샷은 데스크톱과 모바일의 무선·광학·도감·상세·사진 결과·복합 필터·이름 단서·접속 안내·이름 조건 탐색 18장을 생성합니다. 실제 서비스와 같은 `/examguard/` 하위 경로와 HTML CSP를 사용합니다.

## 아직 검증하지 않은 것

실제 스마트안경·스마트폰의 광고 상태와 신호 성능, 실제 iPhone·Android의 카메라/조명 조합, 독립 현장 사진의 기종 식별 정확도는 이 자동 검사에 포함되지 않습니다. WebKit의 iPhone 화면 에뮬레이션은 실제 iPhone 실험과 다릅니다. BLE 테스트는 모의 API 입력이며 신호 수신 검사가 아닙니다. Bluefy는 공식 문서로 Web Bluetooth 제공을 확인했으나, 실제 iPhone에서 ExamGuard와의 호환성은 검증하지 않았습니다. 모의 iOS API의 버튼 활성화 검사는 Bluefy 실기기 시험을 대신하지 않습니다.

복합 규칙 테스트에는 가상의 회사·UUID·바이트만 사용합니다. 같은 회사의 다른 가상 패턴을 후보로 올리지 않는지 검사하며, 실제 제조사 제품의 오탐 감소율을 입증하지 않습니다. 이름 단서 분류도 합성 이름으로 검사하며, 실제 제품이 그 이름을 광고한다는 검증이 아닙니다. 실기기로 검증한 기본 규칙은 아직 배포하지 않습니다.

사진 검색 테스트는 라이선스가 있는 참조 사진의 크롭을 다시 조회합니다. 모델이 로드되고 결과가 도감에 연결되는지 확인하는 통합 검사이며 현장 정확도·적발률의 증거가 아닙니다. 재촬영 사진, 일반 안경, 미등록 기종을 포함한 별도 평가가 필요합니다.

개발 호스트의 샌드박스가 브라우저 실행과 localhost 바인딩을 제한해, 로컬에서는 타입·빌드·Node 테스트·CPU 모델 추론을 실행하고 브라우저 검증은 GitHub Actions에서 실행했습니다. 공개 데모의 HTML·모델·WASM 경로는 별도로 HTTP 응답을 점검합니다.
