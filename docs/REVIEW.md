# 기획안 검토와 구현 결정

검토일: 2026-11-07. 제공된 `code_artifact.md`의 기능 기획과 `examguard.html`의 화면 구상을 검토하여 구현했습니다. 원본 파일의 절대 경로와 비공개 자료는 공개 저장소에 포함하지 않습니다.

프로젝트의 첫 단계는 **모드 A · 교실 전파 탐색**입니다. B · 교탁 위 정밀 광학 판독과 C · 3초 실물 도감은 발견 후 실물을 확인하는 단계입니다. 현재 연결 범위는 [INTEGRATIONS.md](INTEGRATIONS.md), 제조사 코드와 API 역할은 [MODE_A.md](MODE_A.md)에 설명합니다.

## 핵심 보완

| 원안의 가정 | 검토 결과와 반영 |
| --- | --- |
| 수거 뒤 교실은 Zero-RF | 허용 장비·교실 밖 신호·전원을 끄지 않은 기기가 남을 수 있습니다. 전원 종료·수거·허용 장비 3개 준비 항목을 먼저 확인합니다. |
| optionalManufacturerData로 제조사 자동 판별 | 이 옵션은 제조사 데이터 접근 권한 범위입니다. 선택창의 전체 목록이나 기종 분류를 앱에 제공하지 않습니다. 현재는 직접 선택한 기기만 기록합니다. |
| 회사 ID가 스마트안경 시그니처 | 회사 식별자는 제품 종류·소유자 증명이 아닙니다. Meta 0x01AB/0x058E도 단독 판별에 쓰지 않습니다. 원안의 0x0D53=Luxottica는 검증하지 못해 배제했습니다. |
| 활성 BLE 신호면 부정행위 의심 확정 | BLE 광고 부재는 전원이 꺼졌거나 기기가 없다는 증거가 아니며, 신호 발견도 부정행위 증거가 아닙니다. 이름·거리·제조사·소유자를 자동 생성하지 않습니다. |
| 브라우저가 교실 위치/RSSI를 제공 | 일반 requestDevice 결과에는 RSSI·좌석이 없습니다. 외부 수신기 JSON을 가져와 반복 측정 중앙값만 비교합니다. |
| iOS 포함 조명·IR 100% 지원 | getUserMedia·torch 지원 여부를 런타임에서 확인합니다. IR 하드웨어를 웹 필터로 만들 수 없습니다. 사진 입력 대안을 제공합니다. |
| 반사점·녹색 무늬는 카메라/HUD | 나사·리벳·일반 코팅도 반사합니다. 보정 필터와 관찰 위치 도식으로 범위를 한정합니다. |
| 사진으로 위험 확률 계산 | 라벨 데이터·검증 모델 없이 정확한 확률을 제시할 수 없습니다. 사용자 수정 요청에 따라 외형 유사 도감 Top-3 검색으로 구현합니다. |
| 최신 주의 기종 5선 | 위험 순위를 뜻하지 않습니다. 공식 자료가 확인된 Meta, G1, Air 2, Mijia Smart Audio, HUAWEI Eyewear 2를 우선 수록합니다. ‘루체’는 구체 모델·공식 근거를 확보한 뒤 추가합니다. |
| 오프라인 완전 보장 | 앱과 기본 도감은 사전 캐시합니다. 사진 모델은 첫 대조 때 따로 받습니다. 권한·메모리·저장 공간·캐시 삭제의 영향을 받으므로 사전 실기기 점검이 필요합니다. |

모든 전원이 완전히 꺼진 스마트안경은 그 상태에서 전자 기능을 사용할 수 없습니다. 전원을 켜 보거나 페어링할 필요 없이 외형·제품 표기를 확인하고 시험 주관기관의 전자기기 보관 절차를 따르는 흐름을 우선합니다.

## 누구의 기기인지 확인하는 절차

앱은 기기 이름·RSSI·사진으로 사람을 식별하지 않습니다. 발견한 기기를 실물과 연결하고 소지자를 확인하는 일은 기관 절차에 따라 담당자가 수행해야 합니다.

1. 허용 장비와 주변 공간 신호를 먼저 구분합니다. 탐지 이름을 특정 학생의 이름으로 해석하지 않습니다.
2. 외부 수신기를 쓰는 경우 같은 기기 키로 여러 구역을 반복 측정합니다. 측정 구역은 수신기 위치이며 소유자 위치가 아닙니다.
3. 추가 확인이 필요하면 “전자기기 여부 확인을 위해 안경의 모델 표기와 부품을 확인하겠습니다”라고 설명하고 책상 위 실물을 대조합니다. 얼굴 촬영 대신 안경만 촬영합니다.
4. 모델 표기·카메라/충전부 등 관찰 사실을 기록합니다. 전원 상태와 사용 행위를 외형에서 추측하지 않습니다.
5. 소지자 확인·보관·인계는 시험 주관기관의 절차와 담당자 확인으로 마무리합니다. JSON 보고서는 참고 기록이며 인계 확인서나 증거 보전 시스템은 아닙니다.

## 기존 오픈소스와의 관계

아래 비교는 공개 저장소가 설명하는 범위를 기준으로 한 설계 비교이며 성능 비교 실험이 아닙니다.

| 프로젝트 | 주요 초점 | ExamGuard와의 관계 |
| --- | --- | --- |
| [yj_nearbyglasses](https://github.com/yjeanrenaud/yj_nearbyglasses) | 네이티브 앱에서 주변 스마트안경 BLE 관찰 | 네이티브 수신·광고 수집을 대신한다고 주장하지 않습니다. 시험장 절차와 실물 도감에 집중합니다. |
| [BLE-Scanner](https://github.com/BenGeorgie55/BLE-Scanner) | ESP32 BLE 스캔 | 외부 수신기의 관측을 지정 JSON으로 변환해 앱에서 구역별 비교할 수 있습니다. 전용 어댑터는 아직 없습니다. |
| [metadetect](https://github.com/Metrix187/metadetect) | 웹/ESP32 기반 Meta 탐지 도구 | 자동 탐지 영역은 겹칠 수 있으므로 독창성을 주장하지 않습니다. ExamGuard는 준비·사진 도감·관찰·보고서 흐름에 초점을 둡니다. |

실제 차별화는 일반 BLE 목록에 시험장 업무를 연결하는 데 있습니다. 사진은 외부 AI 서비스로 보내지 않고, 연습 데이터가 현장 보고서에 섞이지 않도록 분리하며, 브라우저가 알 수 없는 제조사·위치·소유자는 명시적으로 비워 둡니다.
